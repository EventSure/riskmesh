# Master Agreement Workbench Redesign

## 목적

현재 대시보드의 마스터 계약 설정 화면은 좌측의 좁은 단계 패널과 우측 보조 카드 영역으로 나뉘어 있다. `Policy State Machine`, `Pool 현황`, `프로토콜 이벤트 로그`는 현재 설정 작업의 핵심이 아니며, 마스터 계약 설정 폼은 세로로 길고 스크롤이 제대로 동작하지 않는다.

이 변경의 목적은 사이드바 오른쪽 컨텐츠 영역을 마스터 계약 설정 작업에 집중된 워크벤치로 재설계하는 것이다. 입력 폼은 충분히 넓어져야 하지만, 필드가 과하게 가로로 길어져 읽기 어려워지면 안 된다.

## 최종 방향

채택안은 **폼 최대폭 + 검토 패널** 구조다.

- 마스터 계약 설정 폼은 약 720-760px의 최대폭을 가진 메인 작업 영역에 배치한다.
- 남는 가로 공간은 읽기 전용 검토 패널이 흡수한다.
- 넓은 화면에서는 메인 폼과 검토 패널을 나란히 둔다.
- 중간 폭에서는 검토 패널을 폼 아래로 내린다.
- 좁은 폭에서는 검토 패널을 숨기고 폼만 1열로 표시한다.
- 스크롤은 대시보드 전체가 아니라 워크벤치 컨텐츠 내부에서 정상 동작해야 한다.

## 정보 구조

사이드바 오른쪽의 `tab-contract` 화면은 하나의 마스터 계약 워크벤치로 구성한다.

상단에는 3단계 퍼널 상태를 둔다.

1. 기본 설정
2. 참여사 구조
3. 확인 및 활성화

본문은 현재 단계의 작업 폼과 검토 패널로 나뉜다. 기존의 좁은 세로 아코디언은 제거한다.

## 단계별 디자인

### 1. 기본 설정

기본 설정 단계는 계약 조건을 입력하는 화면이다.

포함 항목:

- 보장 시작일
- 보장 종료일
- 담보 타입
- 계약당 보험료
- 지급 티어
- 약관 설정 실행 버튼

레이아웃:

- 날짜, 담보 타입, 보험료는 2열 그리드로 배치한다.
- 지급 티어는 데스크톱에서 4열 그리드로 표시하고, 중간 폭에서는 2열, 좁은 폭에서는 1열로 표시한다.
- 좁은 화면에서는 모든 입력을 1열로 접는다.
- 입력 폼은 데스크톱에서도 약 720-760px를 넘지 않게 한다.

검토 패널:

- 현재 보장 기간
- 보험료
- 지급 티어 요약
- 필수 입력/검증 상태
- 다음 액션

### 2. 참여사 구조

참여사 구조 단계는 리더, 참여사, 재보험사 구성을 편집하는 화면이다.

포함 항목:

- 리더 지분율
- 참여사 이름
- 참여사 지분율
- 온체인 모드의 참여사 지갑 주소
- 참여사 추가/삭제
- 재보험사 추가/삭제
- 재보험사 이름
- 온체인 모드의 재보험사 지갑 주소
- 재보험 요율 정보

레이아웃:

- 각 당사자는 카드형 편집 블록으로 표시한다.
- 카드 왼쪽에는 역할별 색상 강조선을 둔다.
- 이름/지분율은 한 행에서 편집하되, 좁은 화면에서는 세로로 접는다.
- 온체인 지갑 주소는 같은 카드 내부의 하단 필드로 둔다.
- 지분 합계 100% 검증은 상단 퍼널 상태와 검토 패널에 모두 노출한다.

검토 패널:

- 리더/참여사/재보험사 목록
- 지분 합계
- 지분 합계 유효성
- 온체인 모드에서 필요한 지갑 주소 누락 여부
- 다음 액션

### 3. 확인 및 활성화

확인 및 활성화 단계는 참여자 승인 상태와 활성화 가능 조건을 확인하는 화면이다.

포함 항목:

- 참여사별 승인 상태
- 재보험사 승인 상태
- 온체인 모드 안내
- 마스터 계약 활성화 버튼
- 활성화 가능 여부

레이아웃:

- 승인 대상은 상태 리스트로 표시한다.
- 승인 완료 항목은 명확한 성공 상태로 표시한다.
- 미승인 항목은 다음에 필요한 행동이 보이도록 표시한다.
- 모든 조건이 충족되면 활성화 버튼을 주요 액션으로 강조한다.

검토 패널:

- 승인 완료/대기 개수
- 활성화 가능 조건
- 선택된 마스터 계약 PDA
- 온체인/시뮬레이션 모드 상태
- 다음 액션

## 도움말로 이동할 항목

다음 항목은 마스터 계약 설정 워크벤치에서 제거한다.

- `Policy State Machine`
- `Pool 현황`
- `프로토콜 이벤트 로그`
- 정산 흐름 다이어그램

이 항목들은 사이드바의 `도구` 섹션 아래 도움말 성격의 화면으로 이동한다. 구현은 기존 `tab-inspector`를 `도움말` 표시명의 도움말/인스펙터 화면으로 확장하는 방식으로 한다. 별도의 신규 탭 ID는 만들지 않는다.

도움말 화면은 설명/진단/참고 정보를 담는 보조 화면이다. 마스터 계약 설정을 완료하는 데 필요한 주요 액션은 도움말 화면으로 이동하지 않는다.

## 반응형 규칙

넓은 화면, 1200px 이상:

- 상단 퍼널은 3개 상태 카드를 한 행으로 표시한다.
- 본문은 `메인 폼 + 검토 패널` 2열이다.
- 메인 폼은 최대폭을 유지한다.
- 검토 패널은 남는 공간을 사용한다.

중간 폭, 768px 이상 1199px 이하:

- 본문은 1열로 전환한다.
- 검토 패널은 폼 아래로 이동한다.
- 퍼널은 3개 상태를 유지하되 텍스트가 넘치지 않도록 간결하게 표시한다.

좁은 폭, 767px 이하:

- 검토 패널은 숨긴다.
- 폼은 1열로 표시한다.
- 단계 상태는 컴팩트한 상단 표시로 유지한다.
- 버튼/입력 텍스트가 컨테이너 밖으로 넘치지 않아야 한다.

## 스크롤 요구사항

현재 세로로 긴 컨텐츠가 스크롤되지 않는 문제가 있다. 구현 시 다음 원칙을 지킨다.

- 대시보드 루트와 탭 컨텐츠는 `min-height: 0`을 유지해야 한다.
- 워크벤치 컨텐츠 영역이 `overflow-y: auto`를 가진다.
- 사이드바와 상단 헤더는 컨텐츠 스크롤에 의해 밀리지 않는다.
- 긴 참여사 목록과 긴 온체인 주소 필드가 있어도 주요 액션 버튼에 접근 가능해야 한다.

## 비범위

이번 디자인 변경에서 다음은 바꾸지 않는다.

- 마스터 계약 생성 로직
- 온체인 트랜잭션 로직
- 시뮬레이션 store 동작
- 참여사/재보험사 데이터 모델
- 보험 계약 접수, 오라클, 정산 탭의 업무 로직
- 신규 외부 의존성 추가

## 접근성 및 사용성 기준

- 주요 버튼은 현재 단계에서 하나의 명확한 primary action으로 보인다.
- 비활성 버튼은 왜 비활성인지 주변 상태에서 이해 가능해야 한다.
- 온체인 주소는 잘리지 않거나, 잘릴 경우 전체 값을 확인할 수 있어야 한다.
- 키보드 포커스 순서는 상단 퍼널, 현재 폼, 검토 패널 순서로 자연스러워야 한다.
- 좁은 화면에서 텍스트와 버튼 라벨이 겹치거나 잘리지 않아야 한다.

## 검증 기준

구현 후 다음을 확인한다.

- `tab-contract`에서 마스터 계약 설정이 사이드바 오른쪽 공간의 주 작업 화면으로 보인다.
- `Policy State Machine`, `Pool 현황`, `프로토콜 이벤트 로그`는 계약 설정 화면에서 보이지 않는다.
- 해당 보조 정보는 사이드바 `도구 > 도움말`에서 접근 가능하다.
- 데스크톱 폭에서 폼이 과하게 길어지지 않고 검토 패널이 남는 공간을 사용한다.
- 중간 폭에서 검토 패널이 아래로 이동한다.
- 좁은 폭에서 검토 패널이 숨겨지고 폼이 1열로 동작한다.
- 긴 컨텐츠에서 워크벤치 내부 스크롤이 정상 동작한다.
- 기존 마스터 계약 설정, 참여사 편집, 활성화 흐름의 동작은 유지된다.
